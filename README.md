# RAG with Weaviate

Система ответов по локальным документам на Python. Программа разбивает текст
на фрагменты, получает их векторные представления через API и сохраняет в Weaviate.
Для вопроса она находит похожие фрагменты и передаёт их языковой модели.
Ответ сопровождается названием документа, разделом и подтверждающей цитатой.

## Установка

Нужны Python 3.11 или новее, Docker и ключ к OpenAI либо совместимому API.
Запросы к моделям оплачиваются по тарифам выбранного сервиса.
Команды выполняются из папки проекта.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
docker compose up -d
```

В `.env` укажите `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `EMBEDDING_MODEL` и `LLM_MODEL`.
Модель генерации должна поддерживать ответы по схеме JSON (`json_schema`).
Для OpenRouter используются адрес `https://openrouter.ai/api/v1`, модель векторов
`openai/text-embedding-3-small` и модель ответов `openai/gpt-4.1-mini`.
Файл `.env` не включается в Git.

## Документы и индекс

В `knowledge_base/` есть пять документов о вымышленной службе доставки «Клён».
Все условия и цены вымышлены. Свои документы сохраняйте как `.txt` в UTF-8.
Заголовки обозначаются `#` и `##`, абзацы разделяются пустой строкой.
Текст без заголовков тоже поддерживается.

```bash
.venv/bin/python main.py
.venv/bin/python main.py --index --examples 0
```

Первая команда показывает загруженные файлы, длину текста и примеры фрагментов.
Вторая получает векторы через API, записывает данные в коллекцию `KnowledgeChunk`
и проверяет их чтением из базы. Повторная индексация обновляет записи без дублей
и удаляет устаревшие фрагменты. Папка документов задаёт полный состав индекса.
Пустая папка не очищает существующий индекс.

По умолчанию разделы делятся на фрагменты до 800 символов с перекрытием до 80
символов внутри раздела. Заголовок входит в размер и сохраняется в каждом фрагменте.
Для другой папки и размера:

```bash
.venv/bin/python main.py /path/to/documents --index --chunk-size 400 --overlap 40
```

При смене модели векторов или API задайте новое имя `WEAVIATE_COLLECTION`
и создайте индекс заново. Weaviate доступна только локально; данные сохраняются
в томе Docker. Остановить базу с сохранением данных: `docker compose down`.

## Поиск и ответы

```bash
.venv/bin/python main.py --search "Курьер дважды не застал адресата. Что произойдёт с посылкой?" --top-k 3
.venv/bin/python main.py --ask "Сколько стоит доставка посылки 4 кг внутри одного города?" --show-context
.venv/bin/python main.py --ask "Сколько дней рассматривают претензию о повреждении?" --json
```

`--search` показывает найденные тексты, документы, разделы, `chunk_id` и расстояние.
Чем меньше расстояние, тем ближе смысл вопроса и фрагмента; это не вероятность
правильного ответа. `--top-k` задаёт число результатов поиска, по умолчанию 3.

`--ask` возвращает ответ и источники. `source_name` — имя файла в `knowledge_base/`,
`section_title` — раздел, `chunk_id` — идентификатор фрагмента. Цитата показывает
конкретный текст, на который сослалась модель. Программа проверяет наличие
фрагмента и цитаты в переданном контексте. `--show-context` дополнительно выводит
все результаты поиска, включая отброшенные порогом.

В модель попадают фрагменты с расстоянием не больше `MAX_DISTANCE` (по умолчанию
0.55; можно изменить через `--max-distance`). При отсутствии подходящих фрагментов
или нужных сведений возвращается `insufficient_context`. Ошибка структуры ответа
или непроверяемая цитата дают `invalid_output` и код завершения 1.
Успешный ответ имеет статус `answered`. `--json` выводит ответ, источники и контекст.

## Примеры и сравнение качества

В [examples/questions.json](examples/questions.json) — десять вопросов:
пять с ответом в документах и пять без него. Реальные ответы, найденный контекст,
источники и сравнение с той же моделью без контекста сохранены в
[examples/results.json](examples/results.json).
Результаты сравнения размеров фрагментов и количества найденных фрагментов — в
[examples/quality.json](examples/quality.json).

```bash
.venv/bin/python demo.py --compare
.venv/bin/python evaluate.py
```

Первая команда выполняет десять вопросов и сравнивает первые пять с ответами
без поиска при одинаковых инструкциях модели. Вторая сравнивает настройки
400/40 и 800/80 с одним и тремя результатами поиска на тех же вопросах.
Она использует временные коллекции и сохраняет основной индекс.
Полные результаты новых запусков записываются в `output/`.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
TEST_WEAVIATE=1 .venv/bin/python -m unittest discover -s tests -v
```

Вторая команда также проверяет запись, повторную индексацию и поиск в работающей
локальной Weaviate. Эти тесты используют отдельные коллекции и тестовые векторы;
реальные вызовы моделей проверяются командами демонстрации выше.
